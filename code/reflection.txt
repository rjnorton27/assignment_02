This assignment taught me how to build a small ETL pipeline as a package instead of writing one large script. I learned that the package structure matters because each module has a clear responsibility: Extract gets the raw data, Transform cleans and aggregates it, and Display formats it for a person to read. Working through the public API in init.py also showed me how a package exposes its functions through relative imports so the report files can stay simple and reusable. I also learned that data cleaning is a core part of ETL, because values like None, blank strings, currency symbols, and unreadable text must be coerced safely so one bad value does not break the whole report.

The biggest technical skill I practiced was writing functions like clean_currency and clean_quantity to handle messy input without crashing. That required thinking about real-world data problems, such as strings with "$" and "," characters, values like "N/A", and quantities stored as words or empty strings. I also used accumulator patterns in calculate_total_revenue, summarize_by_item, and find_top_entry to build totals and rankings without duplicating logic. The group-by pattern became clearer when I recognized that summarize_by_day was the same idea as summarize_by_item, just grouped by date instead of item and sorted differently for readability.

What still requires more practice is debugging the pipeline from the bottom up and testing each stage before moving to the final report output. I want to get better at checking whether a bug is in the cleaning logic, the aggregation logic, or the formatting layer, especially when working with seeded datasets. My next steps are to practice building small debug checks earlier in the process, reviewing the public API before writing reports, and testing both unit and integration cases to make sure each module does exactly one job cleanly.
